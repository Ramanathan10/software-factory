# Explainer-video workflow

Use this only after `SKILL.md` and only for an explainer video.

1. State the single idea the viewer should understand. Choose one concrete input that moves through the entire explanation. Verify the logic and factual claims before animating.
2. Start in a recognizable situation and name the question it raises. Introduce the abstract model only when it answers that question. End by returning to the situation with the answer.
3. Pick a visual device: an object whose behavior demonstrates the idea, a diagram that grows one part at a time, or a continuous transformation that preserves the viewer's place. Tie each number and label to the object it describes.
4. Write a short beat-by-beat storyboard. For narration, time each visual reveal to the relevant spoken words; without narration, let brief on-screen lines carry the idea. Do not repeat the entire narration as text on screen.
5. Build and inspect the smallest complete section first. Check source-to-screen accuracy, timing, legibility, reduced-motion alternatives, and the transition into the next section before extending the film.
6. Run the installed CLI's checks and inspect snapshots. Review the rendered file, not only the HTML preview. Record any unverified audio or rendering limitation in the delivery note.

The upstream [explainer reference](https://github.com/heygen-com/hyperframes/blob/e1a8c7f1730149a81d5aa5863b963487a2e3955e/skills/hyperframes/references/types/explainer.md) inspired this concise local workflow. It is adapted for the owner's explanation tasks, not copied as a general-purpose film-production policy.
